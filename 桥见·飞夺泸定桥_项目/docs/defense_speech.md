# 竞赛答辩讲稿（3–5 分钟版，约 1300 字）

各位评委老师好。我是《桥见·飞夺泸定桥》的作者。我想先请大家注意屏幕右侧这一列绿色和黄色的徽章——"已核验"和"待核验"。这两个词，就是我今天要讲的核心。

## 一、为什么做这个作品（约1分钟）

飞夺泸定桥是我们从小就知道的故事，但正因为它"人尽皆知"，网络上的表述反而最混乱：有的说勇士是24人，有的配着张冠李戴的历史照片，有的把艺术创作当成史实传播。作为一名数字媒体技术与新闻传播背景的学生，我提出了一个问题：**红色历史能否以"可追溯"的方式被数字化传播？**

我的答案是这座作品——一座本地可运行的数字历史展览。它和普通红色主题网页最大的区别是：时间轴上的每一个事件、地图上的每一个地点、问答里的每一道题，都可以一路点击，回溯到具体的史料档案。观众看到的不是"我说了什么"，而是"我依据什么说"。

## 二、作品是怎么做的（约2分钟）

第一，**史料先行**。我优先采用权威来源：人民日报"记者再走长征路"系列报道、人民网党史频道、红军飞夺泸定桥纪念馆官网、国家文物局的博物馆年度报告信息系统。2026年10月22日，我逐条访问了这些链接并阅读原文，把访问日期写进档案里。九个时间轴事件对应八条已核验史料，关键史实——比如"240里一昼夜急行军""22名勇士均为党员和入党积极分子"——都有至少两条独立来源交叉印证。

第二，**诚实地标注差异**。史料之间并不总是一致的：渡河小船的数量，一处来源说三条，另一处说几艘；突击队员的伤亡，只有一条来源给出数字。对这些差异，我的处理是：不写进正文当确定结论，而是在史料档案的核验说明里如实记录。桥体的历史沿革、回忆录的版次，我没能完成核验，就老老实实标"待核验"，一个字都不补。

第三，**视觉上同样克制**。我没有使用任何来源不明的历史照片——整个作品没有一张历史图片，所有地图和图形都是自绘的矢量示意图，并且明确标注"非真实地图、无精确坐标"。这样做既规避了版权风险，也避免让艺术化表达冒充历史证据。全部功能本地运行，断网状态下核心内容完全可用，适合现场演示。

技术架构上，作品采用 Python + Streamlit，历史数据与界面代码完全分离在 JSON 文件中，并用八项自动化测试保证事件、史料、地点、问答四类数据之间的关联真实有效、核验状态合法。

## 三、作品的局限（约30秒）

我必须如实说明局限：桥体沿革和回忆录出版信息仍未核验；尚未开展面向真实用户的可用性测试；22勇士的完整名单因历史原因不可考，作品没有也无法补全。这些局限都写在项目说明页里，观众随时可以看到。

## 四、结语（约30秒）

数字媒体竞赛不只是比技术炫不炫，更是比我们如何用技术对待内容。飞夺泸定桥这段历史最动人的地方，是22名勇士中绝大部分人连名字都没有留下；纪念馆用22根无名石柱纪念他们。我用"可追溯"作为这座数字展览的地基，是因为我认为——**历史的尊严在于真实，而承认"待核验"，本身就是一种真实。**

谢谢各位评委。
