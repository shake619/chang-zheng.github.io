# 《桥见·飞夺泸定桥》项目介绍

## 一、作品定位

一座**本地可运行**的红色历史交互数字展览。与常见红色主题宣传网页不同，本作品把
「史料来源追溯」作为第一功能：时间轴上的每个事件、地图上的每个地点、问答中的每道题，
都能点击回溯到具体的史料档案，并明确区分「已核验的历史事实」「待核验内容」与「艺术化示意」。

## 二、作品对应竞赛方向

2026 年第十四届全国大学生数字媒体科技作品及创意竞赛——红色之旅追梦铸魂。

## 三、技术架构

- **表现层**：Streamlit 单页应用（6 个页面模块）+ 自定义 CSS（深红/暖白/深灰/金色数字博物馆风格）
- **数据层**：JSON 文件（events / sources / locations / quiz），历史数据与界面代码完全分离
- **校验层**：Pytest 8 项测试，覆盖数据结构、字段完整性、四类数据间的关联与核验状态合法性
- **可视化**：原生 SVG 示意图（经本地 iframe 组件渲染）+ HTML/CSS 时间轴
- **无后端、无在线数据库、无付费 API、无必需联网功能**，断网可用

## 四、史料收集与核验方法

1. 来源优先级：人民网党史/政治/军事频道（人民日报"记者再走长征路"系列）→ 红军飞夺泸定桥纪念馆官网 → 国家文物局博物馆年度报告信息系统 → 四川长征干部学院网站。
2. 关键史实多来源交叉核验（详见 docs/source_verification.md 的核验矩阵）。
3. 每条史料记录实际访问日期（2026-10-22）。
4. 来源存在差异的内容（小船数量、勇士名单、伤亡数字）不在正文写成确定结论，在史料 notes 中标注。
5. 无法在线核验的内容（S08 桥体沿革、S09 回忆录版次）一律标"待核验"，不做补全。

## 五、创新点

1. **可追溯叙事**：事件 ⇄ 史料 双向跳转、地点 ⇄ 事件/史料 三向关联、问答 → 依据来源。
2. **诚实的核验状态呈现**：核验徽章（已核验/待核验/存在争议）贯穿全部页面，不伪造任何史料。
3. **无风险的视觉方案**：全部自绘示意图，断网可运行，适合现场答辩演示。

## 六、当前局限性（如实披露）

- 桥体历史沿革与回忆录出版信息待核验，相关内容未在正文展开。
- 未获得合法授权的历史照片，视觉表现依赖自绘示意图。
- 尚未开展面向真实用户的可用性测试，无用户测试数据。
- 22 勇士完整名单因历史原因不可考，本作品不作虚构补全。
